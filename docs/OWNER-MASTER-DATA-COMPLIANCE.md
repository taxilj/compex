## Why the remaining 6 areas were not implemented this pass

The owner was asked to scope this engagement (via `AskUserQuestion`, since all 8 areas in one pass would mean guessing priorities) and explicitly chose **"Settings + Organization"** only. The remaining 6 areas (Users, Customer, Vendor, Manufacturer, Product, Category) each still require at least one new Prisma model or substantial field additions to existing models, an additive migration against the shared production database, new audited REST endpoints, new/extended admin UI, and real test coverage — a genuine multi-model initiative, correctly deferred rather than rushed.

## Recommended scoping for the next pass (unstarted, no owner decision yet)

1. **Category/ProductGroup import + admin page** — the 373-row hierarchy is pure data import once the model exists.
2. **Product/Item master** — depends on Category + Manufacturer both existing first.
3. **Customer/Vendor field extensions** — additive columns on existing models, lowest schema risk, but the largest field count (~25 and ~20 respectively).
4. **User field extensions + department-linked permissions** — flagged separately since it touches authorization; per this task's own instruction, no new permission system should be invented without explicit sign-off on what department-based access should actually restrict.
