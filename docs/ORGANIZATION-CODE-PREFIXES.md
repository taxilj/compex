# Organisation code prefixes (F7)

Status: **traced; no numbering rule implemented.** The owner supplied the prefix values but not how they combine into numbers, so nothing was invented.

## Where prefixes live

- Table `organizations` has 13 nullable text columns (`prisma/schema.prisma`, `Organization`, lines 720–733): `invoicePrefix`, `proformaInvoicePrefix`, `packingSlipPrefix`, `cocPrefix`, `orderAckPrefix`, `quotationPrefix`, `salesOrderPrefix`, `purchaseOrderPrefix`, `itemNoPrefix`, `vendorCodePrefix`, `customerCodePrefix`, `contactCodePrefix`, `rmaPrefix`. Added by migration `20260824011235_add_organization_and_settings`.
- Edited through `PATCH /api/v1/admin/organizations` (Zod: optional string, max 20; `admin.organizations.routes.ts`) and the admin **Organization** page (`compex-frontend/src/app/admin/organization/page.tsx`). Changes are audited (bank fields are redacted from the audit entry, Phase 5 F4).

## Where prefixes are used

**Nowhere.** No number generator reads them:

| Number | Generated by | Format today |
|---|---|---|
| RFQ | `modules/rfqs/rfq-number.ts`, Postgres sequence `rfq_counter_seq` | `RFQ-<year>-<6-digit seq>` |
| Quotation | `modules/admin/quotation-number.ts`, sequence `quotation_counter_seq` | `QUO-<year>-<6-digit seq>` |
| Vendor code | typed by staff (`vendorCode`, unique, max 100) | free text |
| Customer / contact code | no field exists | n/a |
| Invoice, proforma, packing slip, COC, order ack, sales order, PO, item no, RMA | no feature built (order/financial workflows are deliberately out of scope) | n/a |

## Owner-supplied values

`KAS CRM.xlsx`, sheet **Organization**, rows 14–27 (format TEXT): invoice `KI`, proforma `KPI`, packing slip `KPCK`, COC `KCOC`, order ack `KACK`, quotation `KQ`, sales order `KSO`, purchase order `KPO`, item no `KPN`, vendor code `KVEND`, customer code `KCUST`, contact code `KCONT`, RMA `KRMA`. Whether these values are already saved in the production Organization row was not checked (it needs an admin login).

## Missing owner decisions

The workbook gives prefixes only. Not specified anywhere I could find:

1. The pattern: prefix + separator + sequence width, and whether the year/month is included (today's RFQ and quotation numbers include the year).
2. Whether the sequence restarts each year or runs continuously.
3. Whether `KQ` replaces the current `QUO-` quotation numbers and `RFQ-` stays, and what happens to numbers already issued.
4. Whether vendor/customer/contact codes become automatic (new `customerCode` and `contactCode` fields would be needed) or vendor codes stay manual.
5. Whether the other prefixes (invoice, packing slip, COC, order ack, sales order, PO, item no, RMA) should drive anything before those workflows exist.

Until these are answered, changing the generators would alter customer-visible numbers on live quotations, so it was not done.
